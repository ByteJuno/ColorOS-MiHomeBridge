# ColorOS MiHome Bridge

`0.4.1-preview`：把米家已选设备接入 ColorOS 17 **控制中心小卡片和设备空间主列表大卡片**。复用原生列表和卡片，状态由米家官方 `ControlsProviderService` 提供，完整设备控制面板继续可用。本轮把宿主 `PanelDevice` / `DeviceStatus` 的字节码契约逐位确认，结论写在 [docs/host-panel-contract.md](docs/host-panel-contract.md)。

## 使用

1. 安装 `dist/ColorOS-MiHomeBridge-0.4.1-preview.apk`。
2. 在 LSPosed 中启用「米家控制中心桥接」，勾选米家 `com.xiaomi.smarthome`、系统界面 `com.android.systemui` 和设备空间 `com.heytap.mydevices`。旧版升级需补勾设备空间。
3. 首次启用或更新后重启手机，让宿主加载新代码。模块不会自行重启手机或系统界面。
4. 打开米家确认登录。在模块中打开「选择设备 / 打开完整面板」，选择米家，保存要显示的设备或手动场景。已经在 0.1.2 保存的选择可以继续使用。
5. 下拉控制中心，在「设备空间」使用卡片。未显示设备空间时，在控制中心编辑页添加。紧凑 2×1 布局显示一台设备，4×1 布局最多显示三台；其余设备可在完整面板中使用。

点击设备空间入口，或在模块中点击「打开设备空间」，可在平板、耳机等原有卡片后看到已选米家设备，最多追加 32 台。大卡片显示名称、官方图标、在线状态及状态文字，点击或长按进入米家详情。大卡片内暂未内嵌调光、调温等控件。

控制中心小卡片点击切换开关或执行场景，长按进入米家详情。精细操作可使用米家详情或完整面板。原生方形小卡片以图标展示，名称和状态提供给无障碍服务；矩形小卡片使用原生文字布局。

如果卡片或完整面板一直处于连接 / 加载状态，请在「米家 → 应用详情 → 耗电管理」中选择「完全允许后台行为」，再打开一次米家。本机实测系统 Hans 会冻结米家控制服务；放开后台活动后恢复响应。该设置会允许米家后台运行，也可能增加耗电。

## 设置项

模块内新增两项显示设置，改动后立即生效（命令通道会要求系统界面重新发布一次面板）。两者都只影响本模块注入的卡片，不改 OPPO 自己的设备与收藏。

| 设置 | 默认 | 作用 |
| --- | --- | --- |
| 主列表米家设备排在原生设备之前 | 关 | 仅影响设备空间主列表：关闭时保留 OPPO 原有设备在前，米家卡片追加在后。控制中心的设备空间只有 1～3 个卡位，米家卡片在那里始终排最前，否则会被卡位裁剪掉。 |
| 点击大卡片直接开关设备 | 开 | 关闭后点击大卡片打开米家详情，与系统卡片行为一致；长按始终打开详情。 |

两处排序之所以不同，是容量决定的：主列表可以滚动，追加在后面不打扰原有设备；控制中心那一条按布局只保留 1～3 张卡（`colspan=4, rowspan=1` 实测为 3），排在后面的卡片会被直接裁掉，米家卡片必须靠前才看得见。

控制中心那一条另外按「能不能动手」排序：可操作的设备优先占住有限的卡位，离线或不可用的设备排到末尾，被裁掉的就是点了也没反应的卡片。

## 本版变化

- **设备空间主列表改为事件驱动**：不再每 1.2 秒跨进程拉一次全量快照（含图标，实测每次可达上百 KB）。米家状态变化时由系统界面主动推送一次通知，列表再按需拉取；可见期间保留 15 秒心跳兜底，连续失败按 3 秒退避，最多 4 级。正在请求时到达的推送会合并成一次补拉，不会并发叠加。
- **主列表不再被超时清空**：单次快照超时只记一次失败并等待重试，已经显示的卡片保持不动，避免网络或服务卡顿时的整列表闪烁。
- **卡片图标按屏幕密度编码**：之前固定最长边 128 像素、单张 16 KiB，在高密度屏上被放大发糊。现在按约 48 dp 的卡片实际尺寸生成（最高 256 像素），单张上限 48 KiB、总量 640 KiB，仍逐级降采样直到放进预算。
- 设备空间主列表的排序做成设置项（默认保持 OPPO 设备在前）；控制中心卡位有限，那里固定「米家优先 + 可操作优先」，避免注入卡片被卡位裁剪掉。
- 新增「点击大卡片直接开关设备」设置，可按需切回系统卡片的「点击进详情」行为。
- 大卡片长按补上原生同款触感反馈。
- 修正图标缓存串页：一个页面退出时会把其它页面已解码的图标一起清掉，重入后需要重新解码。
- 模块只在 API 37 及以上加载，不再写死等于 37；每个注入域（米家服务、控制中心、设备空间主列表）各自独立解析与容错，单点不匹配只降级对应功能，不再整体失效。
- 设置页改为原生设置行样式：分组标题、圆角卡片、分隔线、右侧开关与箭头，点击行有系统涟漪反馈；状态行改为「项目 + 当前值」。深色模式同步调整。
- 米家设备服务可用性判断收敛到一处（模块与设置页共用），并加回归测试。

## 适配与验证范围

已验证的一加 15 基线：`PLK110_17.0.0.105(CN01)`，Android 17 / API 37；SystemUI `17.99.02`；设备空间 `17.25.10`；米家 `11.9.625`。模块使用 libxposed API 101，在 API 37 及以上加载，提供 API 101 的 102 框架亦可加载。

0.4.1-preview 已覆盖安装到上述基线并做了部分实机验证：47 项 JVM 测试、Debug Lint 0 错误、Release 签名构建通过；设备空间主列表 4 台原生 + 3 台米家共 7 台已确认，图标、排序、事件驱动刷新与离线卡片原生灰化样式均已实测，设置页渲染正常。宿主侧结论来自 `scripts/dump_host_dex.ps1` 对 `SystemUI.apk` 的反汇编，原始输出在 `docs/host-dex/`，汇总见 `docs/host-panel-contract.md`。0.4.0 期间修复的两个自引入回归（图标到达后无人通知列表、推送身份未共享被接收侧丢弃）经过见 `docs/validation-0.4.0.md`。真实家电通断电、场景执行、锁屏交互、用户切换、控制中心小卡片尚未在 0.4.1 下重新验收，0.3.0 的完整记录见 `docs/validation.md`。

模块不需要 Home Assistant、账号密码或外部服务器；不读取米家登录凭据，不强制开启锁屏控制。可用功能取决于米家设备服务、当前账号、家庭、地区和设备状态。

## 恢复

在模块中点击「关闭并恢复本模块的改动」，成功后再从 LSPosed 禁用或卸载。系统禁用米家控制服务时可能清除它的已选设备，重新启用后需要重新选择；本次实机已重新选回原来的三台设备。日常暂停接入可只关闭桥接开关。

- 卡片注入仅存在于 SystemUI 和 MyDevices 内存中，关闭后恢复各自原始列表，不写入 OPPO 的持久化收藏。
- 恢复米家设备服务原来的启用状态。
- 只删除本模块新加的 `controls` 独立入口，保留其他快捷开关。
- 用户在系统编辑页调整的设备空间尺寸由系统保存，模块不会回写整份控制中心布局。

保留 `dist/ColorOS-MiHomeBridge-0.2.2-preview.apk` 作为上一稳定预览回退材料。应优先用设置中的关闭开关停用新接入；不要为回退直接卸载并清除数据。

## 构建

需要 JDK 21 及以上、Android SDK 37。设置 `local.properties` 的 `sdk.dir`，在 PowerShell 中执行：

```powershell
$env:JAVA_HOME = '你的 JDK 21 路径'
.\scripts\Build.ps1
```

脚本运行单元测试、Debug Lint 和 Release 构建，复用 `.local/signing/` 中的项目专用签名。首次构建会生成密钥；请私下备份整个签名目录。源码包不包含密钥，因此其他人重建的 APK 无法直接覆盖现有签名版本。

只跑静态验证（不需要签名密钥）：

```powershell
.\gradlew.bat :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```

检查宿主 APK 接口：

```powershell
python -X utf8 .\scripts\check_firmware.py --mihome .\MiHome.apk --systemui .\SystemUI.apk --mydevices .\MyDevices.apk --output .\.local\new-signatures.json
```

这只检查接口定义，不保证其他系统版本兼容。项目不分发米家或系统 APK。

打包源码与更新校验值（需要 Python 3.11+）：

```powershell
python -X utf8 .\scripts\package_source.py
```
